## Project Summary

This project develops a physics-informed neural network (PINN) for optical-fibre signal propagation and studies how far the model can be pushed toward FPGA deployment. The learning pipeline combines SSFM-generated reference data, a DeepONet-style architecture, and NLSE-based physics constraints so that the resulting model is not only data-driven, but also physically structured. The long-term goal is to obtain a model that remains numerically useful after quantization and is practical to compile into a FINN dataflow accelerator for Xilinx Alveo U250.

At the current stage, the repository contains a complete end-to-end workflow covering training, evaluation, trunk freezing, QONNX export, FINN conversion, verification input generation, and board-side output comparison. The project now has two deployment variants. The current mainline variant uses a compact routing-safe configuration with `shape = (1,64)`, `hidden = 64`, and `latent = 32`, and this version successfully completed the FINN deployment flow on the lab machines. A second, more accuracy-oriented variant under `my_build_2` was prepared in parallel with a larger latent width, but that version did not build successfully, which established a practical routing boundary for the current design space.

The mainline deployment is therefore the present hardware baseline. For this variant, board outputs have already been collected for five verification cases and compared against the saved SSFM references after dequantization. This confirms that the deployment flow, driver, and board-side runtime path are operational. The current verification artefacts and plots are stored directly in the repository, including `verification/`, `figures/dequantized_mainline/`, `deeponet_u250_int4_qonnx.onnx`, and `trunk_matrices.npz`. The latest mainline board-comparison summary over five dequantized cases is approximately `rmse = 0.503`, `relative_rmse = 0.724`, `complex_rmse = 0.711`, and `amplitude_rmse = 0.539`.

In other words, the project has already moved beyond software-only modelling and reached a verified FPGA deployment baseline, but model accuracy is still an active optimisation target. The current repository state reflects that balance: one known-good deployment-oriented configuration that builds and runs, one more aggressive variant that maps the hardware limit, and a full set of scripts and English-language notes for repeating the flow on the lab machines.
