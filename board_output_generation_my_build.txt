Minimal process to generate `output.bin` on the board
Compact-complex probe version: INT4 input, expected INT16 output

Current output convention:

- output shape: `(1, 256)`
- `output[0, 0:128] = real(A(L, t_probe))`
- `output[0, 128:256] = imag(A(L, t_probe))`

After rerunning FINN `build_dataflow`, open the generated `driver.py` and confirm:

```text
idt = INT4
ishape_normal = (1, 256)
oshape_normal = (1, 256)
```

If `driver.py` also shows:

```text
odt = INT16
```

then the expected file sizes are:

- `input.bin`: `1 * 256 * 1 = 256 bytes`
- `output.bin`: `1 * 256 * 2 = 512 bytes`

Decoded `output.npy` should have shape `(1, 256)`.
All 256 scalars follow compact-complex layout: first 128 real, last 128 imag.

If your actual `driver.py` uses an `odt` other than `INT16`, follow the values in
`driver.py` instead. The C++ and Python code below assume `INT16`.

Step 1: verify `input.bin` size

```bash
cd /home/xband/finn/my_build/output_u250_bitfile/deploy/driver
python3 - <<'PY'
from pathlib import Path

p = Path("input.bin")
if not p.is_file():
    raise FileNotFoundError("input.bin not found in current driver directory")

size = p.stat().st_size
print("input.bin bytes:", size)
if size != 256:
    raise RuntimeError(f"Expected input.bin to be 256 bytes for INT4 packed input, got {size}")
print("input.bin size check passed")
PY
```

Step 2: copy the timing-enabled XRT program into the driver directory

```bash
cd /home/xband/finn/my_build/output_u250_bitfile/deploy/driver
cp /home/xband/finn/run_finn_xrt_timed_1x256.cpp run_finn_xrt.cpp
```

This template prints board-side inference timing and also writes:


Step 4: run the board-side program to generate `output.bin`

```bash
cd /home/xband/finn/my_build/output_u250_bitfile/deploy/driver
source /opt/xilinx/xrt/setup.sh
./run_finn_xrt 20 2
```

The two numbers mean:

- `20` timed runs
- `2` warmup runs

The program prints mean / std / min / max latency in milliseconds and also
saves the same summary into `board_inference_timing.txt`.

Step 5: quick check of `output.bin` and decode it as `(1, 256)`

```bash
cd /home/xband/finn/my_build/output_u250_bitfile/deploy/driver
python3 - <<'PY'
from pathlib import Path
import numpy as np

p = Path("output.bin")
if not p.is_file():
    raise FileNotFoundError("output.bin not found")

raw = np.fromfile("output.bin", dtype=np.uint8)
print("raw bytes:", raw.size)
if raw.size != 512:
    raise RuntimeError(f"Expected 512 bytes for INT16 (1,256), got {raw.size}")

y_raw = np.fromfile("output.bin", dtype="<i2").astype(np.int32).reshape(1, 256)
np.save("output_raw_int16_1x256.npy", y_raw)
np.save("output.npy", y_raw.astype(np.float32))

print("Saved output_raw_int16_1x256.npy")
print("Saved output.npy")
print("output_raw shape:", y_raw.shape)
print("output_raw dtype:", y_raw.dtype)
print("output_raw min/max:", y_raw.min(), y_raw.max())
print("real first 16:", y_raw[0, :16])
print("imag first 16:", y_raw[0, 128:144])
print("real nonzero:", np.count_nonzero(y_raw[0, :128]))
print("imag nonzero:", np.count_nonzero(y_raw[0, 128:]))
PY
```

Step 6: dequantize on the host machine

After copying `output.bin` or `output_raw_int16_1x256.npy` back into this
repository, run:

```powershell
python dequantize_board_output.py --model deeponet_u250_int4_qonnx.onnx --input verification/case_000/output_raw_int16_1x256.npy
```

For all verification cases at once:

```powershell
python dequantize_board_output.py --model deeponet_u250_int4_qonnx.onnx --cases_dir verification --input_name output_raw_int16_1x256.npy
```

This writes `output_dequant.npy`, which can then be passed directly to
`step6_compare_deploy_output.py`.
